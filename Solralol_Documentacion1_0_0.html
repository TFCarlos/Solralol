Solralol

Panel de control, overlay, historial e inspector para League of Legends, desarrollado con Python y PySide6. Lee datos locales de una partida activa, consulta el historial mediante Riot API bajo demanda, muestra detalles postpartida y ofrece un visor de análisis web por campeón.

PySide6

Interfaz, layouts, señales, hilos, diálogos y visor web integrado.

Live Client + Riot

Datos en vivo desde League local e historial autenticado de Riot API.

Data Dragon

Catálogo, iconos y caché local de campeones y objetos.

Requisitos e inicio

  • Windows con League of Legends instalado y una partida activa, incluida la herramienta de práctica, para los datos Live Client.
  • Python 3.10 o superior y un entorno virtual recomendado.
  • Dependencias principales: PySide6, requests y urllib3.
  • Para el visor integrado de Análisis debe estar disponible PySide6.QtWebEngineWidgets.

Flujo de datos

League local→ GameService→ LiveDataWorker→ MainWindow→ ChampionCard / Overlay

League expone datos de la partida en local. GameService los convierte en un snapshot compacto. El worker los consulta en un QThread; la interfaz recibe el snapshot mediante señales Qt y actualiza widgets exclusivamente desde el hilo principal.

{
  "game_mode": "PRACTICETOOL",
  "game_status": "IN_PROGRESS",
  "game_time": 1234.5,
  "champion_id": "Varus",
  "item_ids": [1055, 3006],
  "local_player": {...},
  "enemies": [...],
  "all_players": [...],
  "local_live_stats": {...}
}
Riot ID→ RiotApiService→ MatchHistoryWorker→ MatchHistoryCache→ Historial / Inspector

El flujo de historial es independiente del timer Live Client. Solo se ejecuta por acción manual del usuario y reutiliza la caché para no repetir descargas de partidas ya conocidas.

API local de League

La base de la API local es:

https://127.0.0.1:2999/liveclientdata

El endpoint principal del proyecto es:

/allgamedata

La respuesta incluye normalmente gameData, activePlayer y allPlayers. Cada jugador puede aportar nombre del campeón, Riot ID, equipo, posición, nivel, objetos, puntuaciones, runas y hechizos de invocador.

GameService

app/services/game_service.py encapsula la comunicación con la API local. No contiene widgets ni código de presentación.

MétodoFunción
request_data(endpoint)Construye la URL de Live Client Data, hace la petición HTTPS, aplica timeout y devuelve JSON.
is_in_game()Detecta si League está exponiendo datos de una partida activa.
get_game_snapshot()Lee allgamedata, localiza jugador local, separa enemigos y entrega el snapshot normalizado.

El jugador local se identifica comparando los datos de activePlayer con los jugadores de allPlayers. Los enemigos son quienes tienen un campo team diferente al del jugador local.

LiveDataWorker

app/services/live_data_worker.py hereda de QObject. Se desplaza a un hilo dedicado mediante moveToThread() y evita que una petición HTTP congele el panel.

SeñalContenidoDestino
snapshot_readySnapshot o None.MainWindow.receive_snapshot
read_failedMensaje de error.MainWindow.show_read_error
 
@Slot()
def read_snapshot(self) -> None:
    snapshot = self.game_service.get_game_snapshot()
    self.snapshot_ready.emit(snapshot)
El worker no debe crear ni modificar widgets. En Qt, los widgets pertenecen al hilo de interfaz.

MainWindow

MainWindow, en app/ui/main_window.py, es la ventana principal actual. Hereda de QMainWindow y organiza cabecera, navegación, Inicio, Análisis, Partida en vivo, Ajustes, workers, historial, visor web y overlay.

Timer y refresco

Un QTimer solicita snapshots locales cada segundo. is_refreshing evita solapar solicitudes si una lectura aún está en curso.

Panel eficiente

El overlay puede actualizarse por snapshot, mientras que las tarjetas se reconstruyen al entrar en partida y a intervalos configurables.

Equipos

Se filtran jugadores con team == "ORDER" y team == "CHAOS"; cada grupo se dispone en cinco columnas.

Controles

Permite mostrar/ocultar overlay, bloquear clics y modificar opacidad con un slider.

Índices de navegación

0 → Inicio
1 → Análisis
2 → Partida en vivo
3 → Ajustes

Los índices del QStackedWidget y los botones de create_navigation() deben mantenerse sincronizados. La pestaña Partida en vivo empieza deshabilitada y se habilita únicamente cuando el snapshot detecta una partida activa.

Orden por rol

TOP → JUNGLE → MIDDLE → BOTTOM → UTILITY

La API puede entregar el jugador local como position: "NONE". Si lleva un hechizo cuyo nombre contiene Smite, se infiere el rol JUNGLE.

Estado sin partida

show_no_game() se llama cuando el snapshot es None. Debe borrar tarjetas cuando proceda, restablecer textos del overlay, poner was_in_game = False, poner cards_built = False y reiniciar el contador de refresco.

ChampionCard

ChampionCard, en app/ui/champion_card.py, representa un jugador. Recibe su diccionario, la marca de jugador local, catálogo de ítems, versión, tiempo de partida y estadísticas locales cuando aplican.

  • Icono del campeón, nombre y Riot ID.
  • Nivel y etiqueta TÚ para el jugador local.
  • KDA, CS, CS/minuto y valor de build.
  • Chips de AP, AD, armadura, MR, crítico, penetración, letalidad y heridas graves.
  • Nota de datos reales o estimados.
  • Resumen de runas e inventario.

Degradado de equipo

La tarjeta debe leer player["team"], no depender de si es el jugador local. En paintEvent(), un QRadialGradient pinta un brillo difuminado individual:

  • ORDER: azul, más visible hacia la parte inferior.
  • CHAOS: rojo, más visible hacia la parte inferior.
  • La zona superior permanece oscura para que el texto conserve contraste.

Los tamaños se mantienen homogéneos mediante una política horizontal expandible, una altura fija y cinco columnas con el mismo factor de expansión en el grid.

Inventario y Role Quest

app/ui/inventory.py transforma la lista player["items"] en slots visuales. Debe devolver siempre un QWidget, incluso si hay slots sin contenido.

ElementoTratamiento visual
Slots 0–5Inventario normal, mostrado en matriz de seis espacios.
Slot 6Trinket: ward, farsight u oracle lens.
ADC/APCLas botas detectadas en cualquier objeto publicado se mueven visualmente al slot especial de botlane.
SupportSe reserva una posición visual para la mecánica de Control Wards de Role Quest.

Limitación de botas

Tras completar la Role Quest, League puede retirar las botas de la lista expuesta por la API local para BOTTOM. Si la aplicación vio esas botas antes, puede retener el último objeto conocido por Riot ID en una caché de memoria. Si nunca se recibió un identificador de botas, no se puede saber de forma fiable cuál lleva el jugador.

OverlayWindow

app/ui/overlay_window.py implementa una ventana flotante que presenta datos rápidos de partida. Su responsabilidad es visual y no debe consultar la API por sí misma.

  • Actualiza tiempo de partida, datos locales y resumen de enemigos.
  • Puede mostrarse u ocultarse desde el panel.
  • Usa setWindowOpacity() para opacidad.
  • Activa click-through con Qt.WindowTransparentForInput.
  • Permite arrastre cuando click-through está desactivado.

Estilos y sombras

app/ui/styles.py define CONTROL_WINDOW_STYLE. Debe incluir paleta, tipografías, bordes, botones, scroll, aspecto de slots, pestaña Análisis e inspector de partida.

No uses text-shadow en Qt Style Sheets. Qt QSS no implementa esa propiedad CSS web y mostrará Unknown property text-shadow.

Para una sombra real alrededor de cada tarjeta puede usarse QGraphicsDropShadowEffect:

shadow = QGraphicsDropShadowEffect(card)
shadow.setBlurRadius(12)
shadow.setOffset(2, 3)
shadow.setColor(QColor(0, 0, 0, 190))
card.setGraphicsEffect(shadow)

Riot API y ajustes

La página Ajustes contiene el campo protegido de Riot API key, el botón Guardar y comprobar y la acción Eliminar clave. La clave se valida contra un endpoint de Riot y se guarda localmente en:

C:\Users\TU_USUARIO\.solralol\settings.json

El servicio SettingsService es responsable de cargar y guardar el JSON, validar la clave y eliminarla. Debe definir self.settings_path en su constructor antes de usar save().

La clave no se incluye en la caché del historial. La caché de partidas y la configuración se mantienen en archivos separados.

Regiones

Riot Account-V1 y Match-V5 utilizan una región de routing, por ejemplo europe; Summoner-V4 utiliza una región de plataforma, por ejemplo euw1. Ambas se conservan en ajustes como riot_account_region y riot_platform_region.

Buscador de invocador e historial

La sección «Actividad reciente» de Inicio permite escribir el Riot ID separado en dos campos: nombre y TAG. El botón Actualizar historial es la única ruta normal para consultar Riot API. El usuario puede abrir cada fila para inspeccionar la partida.

RiotApiService

Resuelve Nombre#TAG a PUUID mediante Account-V1, obtiene IDs recientes desde Match-V5 y recupera detalles de cada partida nueva.

MatchHistoryWorker

Vive en un QThread dedicado. Emite history_ready, history_failed, detail_ready y detail_failed.

MatchHistoryCache

Persiste PUUID, resúmenes, detalles completos y el cooldown de rate limit en ~/.solralol/match_history_cache.json.

Interfaz

La ventana usa history_is_loading para bloquear acciones simultáneas y actualiza la lista solo cuando el worker termina.

Política de solicitudes

  • No consultar historial al iniciar la aplicación.
  • No consultar historial al cambiar de pestaña.
  • No consultar Riot API dentro del timer de un segundo de Live Client.
  • Solicitar por defecto cinco partidas recientes mediante acción manual.
  • Usar PUUID cacheado antes de volver a resolver el Riot ID.
  • Descargar el detalle solo para match_id nuevos o no detallados.
  • Tras una respuesta 429, respetar Retry-After o aplicar 120 segundos de bloqueo local.
  • La futura actualización al terminar una partida debe ejecutarse una sola vez tras la transición in_game → lobby, idealmente con un pequeño retraso para que Riot procese el resultado.
self.history_requested.emit(
    self.riot_api_key,
    game_name,
    tag_line,
    self.riot_account_region,
    self.riot_platform_region,
    5,
)

Inspector de partidas

MatchInspectorDialog se abre al pulsar una fila del historial. Para evitar llamadas repetidas, primero busca el detalle completo en la caché. Si una partida antigua solo tiene resumen, el worker solicita su detalle una única vez y lo persiste con detail_version.

BloqueInformación mostrada
CabeceraVictoria/derrota, retrato de campeón, cola, fecha, duración y KDA del jugador local.
ObjetivosDragones, Barones, Heraldos, torres e inhibidores. Los objetivos se muestran compactos junto a las cabeceras Aliados y Enemigos para ahorrar espacio vertical.
JugadoresCampeón, rol, Riot ID, KDA, CS, oro, visión, nivel y build final.
BuildSeis objetos y trinket cuando existen; los huecos con ID 0 no se pintan.
FallbacksSi no existe un icono de objetivo local, usa emoji: 🐉, 🟣, 👁, 🏰 y 💎.

Las tarjetas se han compactado para que entren ambos equipos, reduciendo el spacing entre tarjetas, entre líneas y en bordes. Las imágenes siguen teniendo prioridad visual sobre texto redundante.

Assets de Data Dragon

DataDragonAssetService centraliza imágenes externas estáticas. Se crea una vez en MainWindow y se pasa a MatchInspectorDialog; no debe instanciarse una vez por jugador.

  • Los campeones se resuelven mediante el catálogo champion.json, porque el nombre visible puede no coincidir con el ID interno. Ejemplos: Kha'Zix → Khazix y Wukong → MonkeyKing.
  • Los objetos se resuelven directamente por ID numérico, por ejemplo /img/item/3047.png.
  • Las descargas se realizan con QNetworkAccessManager, sin bloquear la interfaz.
  • Los assets se guardan en ~/.solralol/ddragon y se reutilizan en aperturas posteriores.
  • Si una imagen falla, se muestra un fallback: abreviatura del campeón o ID del objeto.
Si faltan iconos de objeto, comprobar que el ID no es 0, que la versión configurada de Data Dragon contiene ese objeto y que item_url() usa int(item_id).

Pestaña Análisis

La página Análisis es el visor de referencias para un campeón. Tiene selector de campeón, rol, rango/elo y región. Sus valores se guardan en settings.json como analysis_champion, analysis_role, analysis_rank y analysis_region.

Campeón

Campo de texto. El nombre se convierte a slug para construir URLs, eliminando espacios, apóstrofes y puntos cuando procede.

Rol

Valores internos: top, jungle, middle, adc y support.

Rango/Elo

Filtro guardado para contextualizar las consultas: Todos, Iron+, Bronze+, Silver+, Gold+, Platinum+, Emerald+, Diamond+, Master+, Grandmaster+ y Challenger.

Región

Filtro guardado: EUW, EUNE, NA, KR, BR, LAN, LAS, OCE, JP, TR y RU. Cada fuente puede tener una nomenclatura propia.

Visor integrado

La fuente predeterminada es LoLalytics, cargada en QWebEngineView debajo de los filtros. La UI también permite cambiar a U.GG y LeagueOfGraphs. El botón Cargar análisis carga la fuente seleccionada; Abrir en navegador actúa como respaldo si el sitio no funciona bien dentro del visor.

FuenteURL construidaUso principal
LoLalyticshttps://lolalytics.com/lol/{champion}/build/?lane={role}Builds, runas, objetos, counters, win rate y muestras.
U.GGhttps://u.gg/lol/champions/{champion}/build/{role}Builds, runas, item paths, counters y probuilds.
LeagueOfGraphshttps://www.leagueofgraphs.com/champions/builds/{champion}/{role}Builds, matchups, popularidad, win rate y tendencias.

Los métodos relacionados de MainWindow incluyen set_combo_value(), save_analysis_preferences(), analysis_values(), select_analysis_source(), load_selected_analysis(), open_current_analysis_externally(), analysis_load_started(), analysis_load_finished() y set_analysis_status().

Visor web y bloqueador

El visor puede usar QWebEngineUrlRequestInterceptor para bloquear solicitudes de dominios publicitarios y rastreadores conocidos. El interceptor se instala en el perfil del visor y debe conservarse en una referencia como self.analysis_adblocker.

self.analysis_adblocker = AdBlockInterceptor(
    self.analysis_web_view
)

self.analysis_web_view.page().profile().setUrlRequestInterceptor(
    self.analysis_adblocker
)
  • El bloqueador solo afecta a QWebEngineView dentro de Análisis; no modifica el navegador del sistema ni League.
  • Debe existir un botón para activarlo o desactivarlo y otro para recargar la página.
  • El botón Recargar debe conectarse solo después de crear self.analysis_web_view, o conectar a un método seguro como reload_analysis_page().
  • Un filtro por dominios no elimina todos los huecos visuales ni sustituye a un bloqueador completo basado en listas y reglas cosméticas.
  • Si el visor pierde funciones necesarias de una página, desactivar el bloqueador y recargar.

Cierre seguro

def closeEvent(self, event) -> None:
    self.poll_timer.stop()
    self.overlay.close()

    if self.worker_thread.isRunning():
        self.worker_thread.quit()
        if not self.worker_thread.wait(5000):
            self.worker_thread.terminate()
            self.worker_thread.wait(2000)

    if self.history_thread.isRunning():
        self.history_thread.quit()
        if not self.history_thread.wait(5000):
            self.history_thread.terminate()
            self.history_thread.wait(2000)

    event.accept()

El botón de cerrar personalizado debe conectarse a self.close para asegurar que se ejecute closeEvent().

Mejoras futuras

  • Persistir caché de botas durante una partida y limpiarla al detectar fin de juego.
  • Mejorar la inferencia de rol cuando la API responda NONE.
  • Añadir indicadores explícitos para datos no disponibles o estimados.
  • Reemplazar print() por logging con niveles configurables.
  • Crear pruebas unitarias para cálculo de estadísticas, normalización de rol y detección de botas.
  • Extraer el grid de equipo a un widget dedicado y reducir responsabilidad de la ventana principal.
  • Revisar versiones de League y Data Dragon ante cambios de Role Quest o Live Client API.
  • Implementar actualización automática única del historial tras detectar el fin de una partida, con retraso y sin polling a Riot API.
  • Incorporar análisis personal desde partidas cacheadas: win rate, KDA, CS/min, builds más usadas y matchups propios.
  • Mostrar build más popular y build con mejor win rate como conceptos separados, siempre con muestra, parche, rango, región y fuente.
  • Importar o aplicar runas solo con confirmación explícita, separando runas recomendadas, runas usadas y origen del dato.
  • Diseñar recomendaciones en vivo de baja frecuencia basadas en contexto local, inventario y rivales, sin consultas web durante la partida y tras revisar políticas aplicables.

OBJETIVO DEL PRODUCTO
SolraLoL es una aplicación personal de escritorio para League of Legends hecha con Python y PySide6 en Windows. Combina:
- Datos locales de una partida activa mediante Live Client Data API.
- Tarjetas de ambos equipos y overlay flotante.
- Historial y detalle postpartida mediante Riot API.
- Caché local para reducir llamadas.
- Imágenes estáticas de campeones y objetos mediante Data Dragon.
- Pestaña Análisis con QWebEngineView para consultar fuentes web por campeón.

VENTANA PRINCIPAL
La clase principal actual es MainWindow(QMainWindow) en app/ui/main_window.py. En documentación anterior puede aparecer SolralolWindow/control_window.py: es arquitectura anterior; la implementación actual usa MainWindow/main_window.py salvo que el archivo real indique otra cosa.

ÍNDICES ACTUALES DEL QSTACKEDWIDGET
0 = Inicio
1 = Análisis
2 = Partida en vivo
3 = Ajustes

Al modificar navegación, create_navigation() y build_ui(), mantener esos índices sincronizados. Los botones relevantes son home_button, analysis_button, live_button y settings_button. live_button empieza deshabilitado y se activa cuando se detecta una partida local.

IMPORTS IMPORTANTES
- Qt, QThread, QTimer, QUrl, Signal y Slot provienen de PySide6.QtCore.
- QColor, QPainter, QRadialGradient y QDesktopServices provienen de PySide6.QtGui.
- Widgets como QComboBox, QLineEdit, QLabel, QFrame, QStackedWidget y QVBoxLayout provienen de PySide6.QtWidgets.
- QWebEngineView proviene de PySide6.QtWebEngineWidgets.
- QWebEngineUrlRequestInterceptor proviene de PySide6.QtWebEngineCore.
No duplicar bloques de imports. Verificar paréntesis de cierre y ejecutar py_compile.

LIVE CLIENT
La URL local es https://127.0.0.1:2999/liveclientdata. El endpoint principal es /allgamedata.
GameService normaliza un snapshot con game_time, game_mode, local_player, all_players, enemies y local_live_stats.
LiveDataWorker vive en un QThread. snapshot_requested conecta a read_snapshot(); snapshot_ready llega a receive_snapshot(); read_failed llega a show_read_error().
La interfaz Qt se modifica exclusivamente desde el hilo principal. Los workers no deben crear/modificar widgets.
QTimer consulta el snapshot local cada segundo. is_refreshing evita solapar solicitudes. cards_built, was_in_game, panel_refresh_counter y panel_refresh_every_seconds controlan actualizaciones de tarjetas.
Los equipos usan ORDER y CHAOS. Orden de rol: TOP, JUNGLE, MIDDLE, BOTTOM, UTILITY. Si position es NONE y el jugador tiene Smite, inferir JUNGLE.

OVERLAY Y TARJETAS
ChampionCard usa player["team"] para el color de equipo, no la condición de jugador local. QRadialGradient dibuja brillo azul para ORDER y rojo para CHAOS manteniendo parte superior oscura.
Inventory siempre debe devolver QWidget. Los slots 0–5 son inventario, slot 6 es trinket. Role Quest puede ocultar botas en botlane o Control Wards especiales; aplicar caché visual solo cuando se haya observado previamente el objeto.
OverlayWindow es solo visual: muestra datos resumidos, permite opacidad, arrastre y click-through. No consulta API.

AJUSTES Y RIOT API
SettingsService administra ~/.solralol/settings.json. Debe inicializar self.settings_path en __init__.
La Riot API key se guarda y valida desde Ajustes. No incluir API key dentro de match_history_cache.json.
RiotApiService usa:
- Account-V1 para Riot ID (Nombre#TAG) a PUUID.
- Match-V5 para IDs y detalles de partidas.
- account_region: normalmente europe.
- platform_region: normalmente euw1.

HISTORIAL — REGLA CRÍTICA DE RATE LIMIT
NO añadir polling de Riot API al QTimer de Live Client. No consultar Riot API al arrancar ni al cambiar de pestaña.
El historial se consulta solo al pulsar Actualizar historial y, en el futuro, una única vez después de detectar la transición in_game → lobby, con retraso breve.
El historial por defecto consulta cinco partidas.
MatchHistoryCache persiste ~/.solralol/match_history_cache.json con cuentas, PUUID, resúmenes/detalles por match_id y rate_limit_until.
Reutilizar PUUID y detalles cacheados. Una partida detallada no debe descargarse dos veces.
Ante HTTP 429, leer Retry-After si existe; si no, bloquear localmente 120 segundos. Desactivar la acción temporalmente y mostrar un estado claro.
MatchHistoryWorker corre en QThread y ofrece load_history() y load_match_detail(). Sus señales son history_ready, history_failed, detail_ready y detail_failed.

INSPECTOR DE PARTIDAS
MatchInspectorDialog está en app/ui/match_inspector_dialog.py. Recibe match_detail, item_catalog, data_dragon_assets y parent.
Muestra resultado, retrato del campeón local, cola, fecha, duración, KDA, ambos equipos, roles, Riot IDs, KDA, CS, oro, visión, nivel y build final.
Los objetivos se muestran compactos junto a encabezados Aliados y Enemigos para ahorrar altura: dragon, baron, rift_herald, tower e inhibitor. Si no hay asset local, usar fallback de emoji.
Las tarjetas deben mantenerse compactas: poco spacing entre tarjetas/líneas/bordes, pero objetos e información clave legibles.

DATA DRAGON
DataDragonAssetService se crea una sola vez desde MainWindow y se pasa al inspector. No crear un servicio por jugador.
Descarga imágenes asíncronamente con QNetworkAccessManager y cachea en ~/.solralol/ddragon.
Los campeones requieren resolver el ID interno con champion.json. Ejemplos: Kha'Zix -> Khazix; Wukong -> MonkeyKing.
Los objetos usan ID numérico. Omitir IDs 0 al renderizar; usar fallback si una imagen falla.

PÁGINA ANÁLISIS
create_analysis_page() corresponde al índice 1. Incluye:
- Campo de campeón.
- QComboBox de rol.
- QComboBox de rango/elo.
- QComboBox de región.
- Botón Cargar análisis.
- Selector de fuente: LoLalytics por defecto, U.GG y LeagueOfGraphs.
- QWebEngineView debajo de filtros.
- Botón Abrir en navegador.
- Botón Recargar.
- Bloqueador opcional.

Guardar preferencias en settings.json:
analysis_champion, analysis_role, analysis_rank, analysis_region.
Métodos relevantes que deben existir dentro de MainWindow si la página los usa:
set_combo_value(), create_analysis_source_row(), save_analysis_preferences(), analysis_values(), open_analysis_url(), open_ugg_analysis(), open_lolalytics_analysis(), open_leagueofgraphs_analysis(), set_analysis_status(), select_analysis_source(), load_selected_analysis(), open_current_analysis_externally(), analysis_load_started(), analysis_load_finished().

URLs base actuales:
LoLalytics: https://lolalytics.com/lol/{champion}/build/?lane={role}
U.GG: https://u.gg/lol/champions/{champion}/build/{role}
LeagueOfGraphs: https://www.leagueofgraphs.com/champions/builds/{champion}/{role}
No asumir que parámetros no documentados de rango, región o parche son estables. El usuario puede aplicar filtros adicionales desde el sitio web.
No cargar webs por polling ni durante una partida. La carga automática solo es admisible cuando exista un campeón ya guardado y la UX lo requiera explícitamente.

BLOQUEADOR DEL VISOR
AdBlockInterceptor hereda de QWebEngineUrlRequestInterceptor. Debe hacer únicamente comprobaciones rápidas en memoria de dominio/URL y usar info.block(True) para anuncios/rastreadores.
Mantener referencia viva: self.analysis_adblocker. Si no se conserva, Python puede destruir el interceptor.
Crear self.analysis_web_view antes de conectar un botón directamente a self.analysis_web_view.reload. Como alternativa, usar un método seguro reload_analysis_page().
El bloqueador solo afecta al visor integrado. Debe poder desactivarse y recargarse si rompe una página.

ERRORES YA OCURRIDOS Y PREVENCIÓN
- NameError QPainter: falta import desde PySide6.QtGui.
- AttributeError set_analysis_status: el método se pegó fuera de MainWindow o no se añadió.
- AttributeError open_leagueofgraphs_analysis: callback no definido dentro de MainWindow.
- AttributeError analysis_web_view: el visor se referencia antes de crearse.
- SettingsService no tiene settings_path: inicializar la ruta en __init__.
- QThread destroyed while running: parar poll_timer y cerrar worker_thread e history_thread mediante quit() + wait() en closeEvent().
- None passed to addWidget: cada fábrica visual debe devolver QWidget.
- QSS no soporta text-shadow: no usar esa propiedad.
