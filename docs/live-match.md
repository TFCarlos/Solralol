# Live Match and overlays

`backend/live_match.py` owns one lazy Live Client/LCU monitor. `live.snapshot` returns its cached latest state; the Electron shell publishes snapshots to stable overlay windows, so navigation does not start another tracker. Each overlay receives only its bounded view data. Settings previews render the same React `OverlayContent` component with isolated sample data.

The six panels are Gold Difference, Alerts, Threat/BattleScore, Recommended Purchase, Enemy Last Recall, and Ability Level-Up Recommendation. Gold, threat, alerts, and purchase use backend calculations and recommendations. Settings control visibility, opacity, scale, click-through, and TAB-only visibility where applicable.

Enemy Last Recall is based on enemy inventory observations. A detected paid inventory change can provide an inferred shop baseline, but neither Live Client nor the tracker exposes a confirmed Recall timestamp. Death pauses the interval; the first observed alive state after death resets it to a respawn baseline. The tracker distinguishes inferred purchase, observed respawn, first observation, unknown, and dead states.

Ability level-up uses observed local champion level and Q/W/E/R ranks plus the existing local champion analysis order. Unspent points are derived from the observed ranks, including after reconnecting or opening the overlay mid-match. The next highlight is the earliest unmet legal rank in the recommended sequence; it disappears once the point is spent. Unavailable ranks or order produce no highlight. The panel is always click-through. Live Client exposes ability ranks but not exact ability HUD geometry, so Electron positions the marker from the game client rectangle and saved anchor/slot-spacing calibration.

Electron obtains the League game client rectangle in physical pixels and converts it to display coordinates for overlay placement. Windowed and borderless modes are intended targets; exclusive fullscreen can prevent external windows from appearing. Windows stacking, DPI, TAB timing, and HUD calibration require interactive validation on the target system.

## In-game overlays (October 2026)

The Electron main process owns the five overlay windows (gold, alerts, items, recall, abilities). A shared 450 ms Win32 check enumerates visible, non-minimized top-level windows in Z order, verifies the actual League game executable, skips DWM-cloaked windows and the registered overlay HWNDs, and measures occlusion over the game and each overlay. Focus on another monitor alone does not hide overlays. A heavily covered game hides all overlays; a window covering one panel hides that panel. Windows remain allocated across visibility changes. League Client and Riot Client do not qualify. Settings previews remain inside the main application.

Gold difference uses the current Live Client playerlist inventory and full `gold.total` item prices in the bundled item catalog. Trinkets, consumables, and wards are excluded. Unknown items and ambiguous/missing roles remain unavailable. A team total requires five unique, priced same-role pairs; a genuine zero is displayed as `0`. The Live Client playerlist does not always provide reliable lane positions, so some rows may remain unavailable, especially in Practice Tool or custom matches. No kill, assist, or CS estimate is used by this overlay.

The item cards use the three ranked Live Recommendation rows. `synergy_score` is the raw score from the synergy engine before live threat and purchase adjustments; it is shown in points because this score is not a percentage. The card order still follows the engine's final ranking.

The Live Client endpoints currently consumed by Solralol do not expose confirmed Recall completion or cancellation events. Inventory changes are only inferred purchases and are **not** shown as completed recalls. The recall panel shows a game-time timer after an observed respawn, a dead state while dead, and an unavailable mark otherwise. Its title describes the intended feature; a reliable recall event source is needed before confirmed recall timers can be provided.

Overlay editing is a transient mode toggled from Settings or the configured Ctrl+Alt+Shift+letter shortcut (default O), including when League is closed. Enabled panels open with clearly marked sample data, retain their configured scale and opacity, and can be dragged independently. Each position is saved as DIP coordinates and clamped to a connected display. Leaving edit mode restores normal click-through and occlusion rules. The shortcut is registered once by Electron; no global mouse hook is installed. Exclusive fullscreen, multi-monitor DPI, in-game drag behavior, and real window occlusion still require interactive Windows validation.

The secondary icon on each item recommendation uses `LiveRecommendationService.purchase`, which walks the catalog `from` tree against current owned items, current unspent gold, map availability, and inventory slots. The UI renders it only for a validated `buy` result; `save`, `unknown`, and `full` results have no purchase badge. Affordability and inventory changes are recalculated from the shared two-second live snapshot.

## Alert notifications

`OverlayAlertTracker` uses the same Live Client snapshot as Live Match. It keeps a bounded temporary queue (eight game seconds by default, configurable in Settings) and up to three visible notices. Early objective warnings and completed-item inventory additions are temporary. Objective and structure notices reappear as persistent countdowns during the final ten game seconds. Renderer interpolation makes the seconds readable between shared two-second snapshots; the backend's game time remains authoritative. At the predicted time, a countdown disappears without claiming a confirmed spawn. The Electron Alerts window remains allocated but hidden when there are no current notices, and normal gameplay always passes mouse input through it. Editing mode shows sample notices.

Inhibitor notices require exact `Barracks_T1/T2_L/C/R1` IDs and a matching `InhibRespawningSoon` event. The L/C/R segment identifies TOP/MID/BOT; the T1/T2 segment identifies structure ownership, independent of the local allied side. A destruction event alone does not establish a reliable deadline. `InhibRespawned` clears the tracked structure. Nexus turret countdowns require exact `Turret_T1/T2_C_01/02_A` IDs, CLASSIC mode and a known supported game version. The backend reads the installed version once per live session from the existing LCU connection when Live Client omits it. If that read is unavailable, no Nexus respawn deadline is shown. The 180-second Summoner's Rift rule is patch gated; other modes never inherit it. These identifiers and timers still require real-match validation across both sides and patches. Purchase notices are inventory observations, never confirmed shop transactions; initial inventory, old items reappearing after undo/sale, and gaps in observations are suppressed.

Rule context: [Riot Live Client Data API](https://developer.riotgames.com/docs/lol), [Riot's three-minute Nexus turret rule](https://www.leagueoflegends.com/es-es/news/game-updates/patch-25-s1-1-notes/), [Riot 2026 Nexus turret update](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/), [Riot Void Grub and Herald timings](https://www.leagueoflegends.com/en-gb/news/game-updates/patch-25-09-notes/). The Live Client endpoint does not expose a direct item-purchase event or a Nexus-turret respawn event, so those cases remain observation or patch-rule based.
