1. Introducción y características

Solralol es una aplicación de escritorio para Windows que combina, en una única interfaz paginada, la información de tu partida en tiempo real, el análisis de drafts, tu historial, la grabación de vídeos con marcadores de eventos y análisis con IA (Google Gemini). Se conecta a cinco fuentes:

FuenteEndpoint / origenUso principal
Live Client Data APIhttps://127.0.0.1:2999/liveclientdataSnapshots en vivo (oro, CS, KDA, objetivos, eventos)
LCU API (cliente local)lockfile de Riot Games\League of LegendsChamp select, importar runas/objetos/hechizos
Riot API (oficial)account-v1 / match-v5 / plataformaHistorial, perfil, detalle y sync post-partida
Gemini APIgenerativelanguage.googleapis.com/v1betaAnálisis IA de partidas y re-análisis de campeones
Data Dragon · U.GG · OP.GG · LolalyticsCDN y webs públicasCatálogos, iconos, winrates y builds

Resumen de funciones

Partida en vivo

Recomendaciones (LiveRecommendationService), amenazas, métricas y apertura automática del diálogo de análisis.

Overlay en juego

Paneles Oro / Alertas / Rivales, opacidad, avance de alertas, modo solo-Tab y sonidos (objetivo, dragón, compra enemiga).

Grabación automática

ffmpeg con presets de calidad/bitrate/audio, límite en GB, marcadores de eventos y biblioteca con reproductor.

Draft tool

Se abre solo en selección de campeones: análisis de composiciones e importación de build, runas y hechizos al cliente.

Análisis local

Afinidad, counters, curva de poder, spike, editor JSON de campeones/objetos y recálculo de sinergias.

Partidas guardadas

Sesiones JSON + vídeos con sidecars, sincronización con Riot y reproductor post-partida con sidebar.

Historial e IA

Historial con caché, gráfica SoloQ, inspector de partidas y análisis con modelos Gemini (con fallback).

Ajustes

Cuatro tarjetas: API de Riot, Grabaciones, Overlay e IA Gemini, persistido en ~/.solralol/settings.json.

Interfaz paginada: el sidebar de MainWindow usa índices fijos en el QStackedWidget: Inicio(0) · Análisis(1) · Partida en vivo(2) · Partidas guardadas(3) · Grabaciones(4) · Ajustes(5) (HOME_PAGE_INDEX … SETTINGS_PAGE_INDEX). La pestaña «Partida en vivo» está deshabilitada hasta detectar una partida.

3. Instalación y ejecución

Requisitos

  • Windows (overlay con user32, grabación con ffmpeg, LoL de escritorio).
  • Python 3.13 (probado; 3.11+ debería funcionar).
  • League of Legends instalado (LCU y Live Client Data API).
  • ffmpeg en el PATH o en una ruta conocida (ver §4).
  • Clave de Riot API (developer portal) y, opcionalmente, clave Gemini.

Opción A · scripts incluidos

python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
run.bat                :: ejecuta la app con el .venv
activate_env.bat       :: solo abre una consola con el .venv activado

Opción B · manual

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py

En VS Code existen tareas y lanzamientos en .vscode/tasks.json y .vscode/launch.json («Run Solralol») que ejecutan main.py.

Arranque

  1. main.py establece el AppUserModelID Solralol.App (icono correcto en la barra de tareas) y un filtro de mensajes de Qt.
  2. Muestra StartupWindow y carga el catálogo de objetos en un worker (load_catalog → data_dragon.load_item_catalog()).
  3. Construye MainWindow con showMaximized(), arranca los workers, el ChampSelectWorker, el TabHotkeyService y la ventana OverlayWindow.
Dependencias en uso real: PySide6 (+ shiboken6), requests, urllib3, beautifulsoup4 y imageio-ffmpeg. El resto de requirements.txt (PyQt5, customtkinter, pyqtgraph, numpy, keyboard, bottle, pywebview, pythonnet…) es legado: no se importa dentro de app/ (algunos pueden usarlos los scripts de debug de la raíz).

4. Configuración (tarjetas de Ajustes)

Todo se persiste en %USERPROFILE%\.solralol\settings.json mediante SettingsService (app/services/settings_service.py).

4.1 Tarjeta «API de Riot»

  • Campos: clave API, nombre de invocador (riot_game_name_input), tag (riot_tag_line_input), región plataforma/base (p. ej. euw1 / europe).
  • Botón «Guardar y comprobar» → save_and_validate_api_key: valida la clave contra la API de plataforma en línea y guarda riot_api_key, riot_game_name, riot_tag_line, riot_platform_region, riot_account_region.
  • Necesaria para: historial (history_requested), perfil, detalle de partida y sincronización post-partida.

4.2 Tarjeta «Grabaciones»

  • Auto-grabado: al detectar partida start_match_recording(); al terminar, stop_match_recording() (configuración RecordingConfig con recording_auto).
  • Calidad: presets 1080p60 / 1080p30 / 720p60 / 720p30 (QUALITY_PRESETS), bitrate (BITRATE_PRESETS + DEFAULT_BITRATE), audio (AUDIO_MODES/AUDIO_MODE_LABELS).
  • Límite en GB: LIMIT_MIN_GB–LIMIT_MAX_GB (por defecto LIMIT_DEFAULT_GB); la grabación se corta al superarlo.
  • Carpeta: default_recordings_dir() (editable). RecordingLibrary indexa los .mp4 y sus sidecars .json.
  • ffmpeg: find_ffmpeg() busca en PATH, ~/.solralol/ffmpeg, C:\ffmpeg, LocalAppData, Chocolatey y el binario de imageio-ffmpeg.

4.3 Tarjeta «Overlay»

  • Paneles visibles: Oro, Alertas y Rivales (etiquetas PANEL_LABELS de overlay_window.py).
  • Opacidad: opacity_slider → OverlayWindow.set_opacity (valor mostrado en opacity_value).
  • Avance de alertas: alert_lead_slider → set_alert_lead_seconds (avisa antes de que aparezca un objetivo).
  • Modo solo-Tab: TabHotkeyService (polling de la tecla con GetAsyncKeyState, ~100 ms) muestra/oculta el overlay con Tab.
  • Sonidos: tipos (objetivo, dragón, compra enemiga) y volumen sound_volume_slider → OverlaySoundService vía overlay.set_sound_volume().
  • Botones: «Mostrar overlay» y control de grabación («Detener grabación»).

4.4 Tarjeta «IA Gemini (Google AI Studio)»

  • Pasos en la propia tarjeta: aistudio.google.com → «Get API key» → «Create API key» (clave AIzaSy…).
  • Campo con echo password + botón «Guardar y comprobar Gemini Key» → save_and_validate_gemini_api_key (valida contra v1beta/models) y «Eliminar clave Gemini».
  • Alimenta el análisis de partidas (match_ai_analyzer_service) y el re-análisis de campeones (champion_ai_analyzer_service).

5. Guía de uso por pestañas y ventanas

5.1 Pestaña Inicio

  1. Configura tu Riot ID (nombre + tag) en Ajustes o directamente en Inicio.
  2. Pulsa Refrescar historial (refresh_history_button): MatchHistoryWorker carga las partidas con caché (MatchHistoryCache), se rellenan las filas, el estado (set_history_status: cargando / error / OK) y la gráfica SoloQ (elo reconstruido con calculate_elo_points(tier, rank, LP) sobre la cola 420).
  3. Accesos: Abrir análisis local, Abrir herramienta de draft y Abrir análisis en vivo (open_live_analysis_button, deshabilitado sin partida).
  4. Tres métricas (jugador, modo, sesión) se actualizan con cada snapshot; con League abierto pero sin partida muestra «League abierto · sin partida» y «Esperando una partida» (show_no_game()).
  5. Cada fila del historial puede abrirse en el inspector de partidas (MatchInspectorDialog).

5.2 Pestaña Análisis · LocalAnalysisDialog

Tres sub-pestañas (QTabWidget):

  • Afinidad y gráficos: combo de campeón + estilo (AD/AP/verdadero), barras de composición de daño, curva de poder (PowerCurveWidget), radar de atributos, aliados recomendados, counters y «buenos contra» (SynergyRecommendationService + PlaystyleService).
  • Actualizar winrates: botones para el campeón actual o todos → ChampionScraperWorker raspa U.GG con delay de 0.8 s (también OP.GG/Lolalytics en el servicio) y descarga iconos de runas (versión 16.17.1).
  • Editar campeones: editor de JSON (data/champions_strict.json), «Guardar campeón» y «Re-analizar con IA» → ChampionAIWorker (Gemini reescribe los atributos subjetivos; tooltip: usa Gemini AI (Google AI Studio)).
  • Editar objetos: editor de legendary_items_strict.json, «Recalcular sinergias del objeto», «Recalcular todos los objetos» (ItemSynergyCalculator: synergy_multipliers y counter_weights) y «Guardar objeto».

5.3 Pestaña Partida en vivo

  1. Al entrar en partida se habilita la pestaña y LiveMatchTracker empieza a muestrear cada ~2 s (máx. 50 sesiones guardadas).
  2. Se abre automáticamente LiveMatchAnalysisDialog con la sección en vivo: recomendaciones (LiveRecommendationService.analyze), tarjeta de amenazas y acciones.
  3. Botones clave: «📊 RECOMENDACIONES» (muestra el panel), «🤖 ANALIZAR PARTIDA CON IA» (_start_ai_analysis → confirmación → MatchAIWorker), «📄 Ver Log de Partida» y «🔄 Re-analizar con IA» (o «Analizar Partida con IA» si aún no hay resultado), «📋 Copiar Log», «🚀 Comenzar Análisis con IA», «Cerrar».
  4. El resultado de la IA queda guardado en MatchLogService y se puede copiar.
  5. El overlay se actualiza con cada snapshot y con los eventos (objetivos, compras); si el auto-grabado está activo, la grabación empieza sola.
La IA usa la clave Gemini de Ajustes; si falta o falla, se prueban varios modelos con fallback y se informa del error sin bloquear la interfaz.

5 (cont.) · Pestañas restantes y ventanas especiales

5.4 Pestaña Partidas guardadas

  1. refresh_saved_games() carga en worker las sesiones del tracker, los vídeos de RecordingLibrary y los sidecars (puede haber JSON de cientos de MB); muestra «Cargando partidas guardadas…».
  2. Si ya hay una carga en curso, la nueva petición se marca pendiente y se repite una sola vez al terminar (anti-flooding; la pestaña Grabaciones también dispara este refresco).
  3. Cada fila ofrece: Abrir análisis, Sincronizar (request_saved_session_sync(session_id) → PostgameSyncWorker), Abrir vídeo (open_replay_window) y Borrar (delete_saved_game_session → LiveMatchTracker.delete_saved_session).
  4. Al terminar una partida en vivo, finish_live_session() refresca esta pestaña automáticamente.

5.5 Pestaña Grabaciones · RecordingsPage

  • Lista de vídeos de la carpeta de grabaciones con su sidecar .json (KDA, marcadores, eventos).
  • Reproductor (QMediaPlayer) con slider (seek_requested), marcadores clicables y tarjeta de KDA/resumen (marker_counts, markers_summary).
  • Botones: refrescar, borrar vídeo, abrir carpeta (open_folder_requested), detener grabación (stop_recording_requested → «Detener grabación» en MainWindow, que no cierra la sesión) y abrir ventana (open_window_requested → PostgameReplayWindow).
  • Se sincroniza con el estado real de RecordingService (sync_recording_state()).

5.6 Pestaña Ajustes

Ver §4 (cuatro tarjetas: API de Riot, Grabaciones, Overlay e IA Gemini).

5.7 Ventana de draft (DraftToolDialog)

  • Se abre automáticamente al entrar en selección de campeones (_on_champ_select_started) y se actualiza con cada cambio (update_from_lcu_session); al terminar el draft se cierra y se prepara la navegación a «Partida en vivo».
  • Analiza con DraftAnalyzerService: composiciones por rol, desglose de daño (AD/AP/verdadero), curva de poder, fase de spike, bans sugeridos, runas/hechizos y objetos situacionales.
  • Botones de importación al cliente vía LCU: página de runas (import_rune_page), set de objetos (import_item_set) y hechizos (import_summoner_spells).

5.8 Reproductor post-partida (PostgameReplayWindow)

  • Abre el vídeo de la sesión con sidebar (PostgameSidebar): desglose de daño, objetivos y estadísticas rellenadas por el sync post-partida.
  • Timeline (LiveTimeline) con marcadores de eventos; jump_to_game_time() sincroniza el vídeo con el tiempo de juego.
  • «Adoptar» la sesión por id, ventana temporal o richness; recarga del desglose (reload_breakdown), pantalla completa y atajos de teclado.

5.9 Inspector de partidas (MatchInspectorDialog)

  • Cabecera de la partida (cola, duración, resultado), objetivos compactos, tarjetas de equipo con filas de jugador (campeón, KDA, CS, objetos con iconos Data Dragon), posición y nombre de cola; botón «buscar jugador».

5.10 Overlay (OverlayWindow) y arranque (StartupWindow)

  • Overlay sin bordes, always-on-top y click-through (WindowTransparentInput / WA_TransparentForMouseEvents): los clics pasan al juego.
  • Paneles PANEL_LABELS (Oro, Alertas, Rivales), posiciones persistentes, opacidad y avance de alertas; aviso de grabando cuando set_recording(True).
  • Sonidos (OverlaySoundService, winsound): campana de objetivo (660 Hz), doble tono de dragón (990 Hz) y aviso de compra enemiga (520 Hz doble), con volumen global.
  • Se limpia al terminar la partida; con modo solo-Tab solo aparece mientras se mantiene pulsada Tab.
  • StartupWindow: pantalla de carga con el catálogo de objetos antes de la ventana principal.

6. Flujos de datos

6.1 Selección de campeones (LCU)

ChampSelectWorker (QTimer, 1.5 s → LCUService.is_champ_select_active / get_champ_select_session) ├─ champ_select_started → MainWindow._on_champ_select_started → abre DraftToolDialog (auto) ├─ champ_select_updated → dialog.update_from_lcu_session(session) └─ champ_select_ended → cierra DraftToolDialog + navega hacia «Partida en vivo» DraftToolDialog → DraftAnalyzerService (roles, daño, curva de poder, spike, bans, runas, objetos) → LCUService.import_rune_page / import_item_set / import_summoner_spells

LCUService lee el lockfile (usuario, puerto y token) en las rutas típicas de instalación (C:, D:, E:, F: Riot Games\League of Legends) y autentica las peticiones REST locales.

6.2 Partida en vivo (Live Client Data API)

GameService (https://127.0.0.1:2999/liveclientdata · verify=False) gamestats → is_in_game() · allgamedata+eventdata → get_game_snapshot() ↓ LiveDataWorker (QThread de app/services, sondeo ≈2999 ms) ├─ snapshot_ready → MainWindow.receive_snapshot │ · actualiza overlay, métricas del home y pestaña «En vivo» │ · primer snapshot de la partida → start_match_recording() (si auto) + LiveMatchTracker.start() │ · LivePlayerMetricsService + contadores por equipo ├─ live_analysis_ready → MainWindow.receive_live_analysis │ · LiveRecommendationService.analyze → recomendaciones y amenazas │ · actualiza LiveMatchAnalysisDialog y paneles/alertas del overlay └─ game_ended → MainWindow.handle_game_ended → finish_live_session("game_end") · LiveMatchTracker.finish() → sesión JSON (máx. 50) · stop_match_recording() con marcadores de eventos (si aún graba) · schedule_postgame_sync(session) → PostgameSyncWorker · refresh_saved_games() y cierre del diálogo en vivo

Si se pierden snapshots seguidos en partida, count_lost_snapshot() corta la grabación (LIVE_LOST_POLLS_BEFORE_STOP) para no dejar el vídeo abierto. finish_live_session() es idempotente.

6.3 Historial, perfil e inspector (Riot API)

refresh_history_button → history_requested → MatchHistoryWorker (QThread) RiotApiService: account-v1 (gameName+tagLine) → match-v5 (ids y detalles) MatchHistoryCache (~/.solralol/match_history_cache.json, versión 2, TTL + cooldown por rate-limit) ├─ history_ready → filas del historial + gráfica SoloQ (cola 420, calculate_elo_points) ├─ profile_ready → nivel/rangos → métricas del Inicio └─ detail_ready → MatchInspectorDialog (objetivos, equipos, objetos) history_failed/detail_failed/profile_failed → set_history_status(mensaje, "error")

6.4 Análisis con IA (Gemini)

LiveMatchAnalysisDialog.start_ai_analysis (confirmación «🚀 Comenzar Análisis con IA») → MatchAIWorker (QThread) → match_ai_analyzer_service.analyze_match(...) modelos con fallback: gemini-2.5-flash-lite → gemini-2.5-flash → gemini-flash-latest → gemini-2.0-flash-lite → gemini-2.0-flash → gemini-1.5-flash-latest → MatchLogService.save_log(...) → «📄 Ver Log de Partida» / «📋 Copiar Log» LocalAnalysisDialog «Re-analizar con IA» → ChampionAIWorker → champion_ai_analyzer_service modelos: gemini-2.5-flash → gemini-2.0-flash → gemini-1.5-flash (+ fallback) → actualiza atributos subjetivos del campeón en champions_strict.json («Guardar campeón»)

6.5 Historial de winrates (scraping)

LocalAnalysisDialog (actualizar 1 campeón o todos) → ChampionScraperWorker (QThread, delay 0.8 s entre peticiones) → champion_scraper_service: U.GG (JSON), OP.GG (_parse_opgg), Lolalytics (JSON/HTML) → download_all_rune_icons("16.17.1") → data/rune_icons/

9. Ciclo de overlay, grabación y sincronización

9.1 Overlay

  1. Se crea en el arranque de MainWindow (posición y opacidad persistentes en Ajustes).
  2. Con cada snapshot se envía un snapshot request y el overlay repinta los paneles Oro / Alertas / Rivales.
  3. Alertas (OverlayAlertService): umbrales de tiempo antes de objetivos (barón, dragón, heraldo…), amenazas de compra enemiga y avance configurable (alert_lead_seconds).
  4. Sonido (OverlaySoundService): play_objective_spawn (660 Hz), play_enemy_buy (520 Hz doble) y tono de dragón (990 Hz); volumen global y activación por tipo.
  5. Visibilidad: botón «Mostrar overlay» o modo solo-Tab (TabHotkeyService, GetAsyncKeyState a ~100 ms). Clics transparentes: WindowTransparentInput + WA_TransparentForMouseEvents.
  6. Indicador de grabación activa (set_recording) y limpieza al terminar la partida.

9.2 Grabación

  1. Inicio: si recording_auto, el primer snapshot en partida dispara start_match_recording() → RecordingService.start() lanza ffmpeg con el preset de calidad/bitrate/audio elegidos y crea RecordingSessionInfo.
  2. Durante: límite de GB, indicadores en overlay y pestaña Grabaciones; «Detener grabación» manual deja la sesión viva para que el fin de partida cierre todo correctamente.
  3. Fin: stop_match_recording(reason, completed_session) genera el .mp4, el sidecar .json con KDA y los marcadores construidos desde los eventos (build_markers, OBJECTIVE_MARKERS/MARKER_LABELS: torres, dragones, barones, kills…, ajustados al game time offset).
  4. Biblioteca: RecordingLibrary indexa vídeos y sidecars; RecordingsPage y PostgameReplayWindow los consumen.
  5. Seguridad: si la API local deja de responder en mitad de la partida, count_lost_snapshot() corta la grabación tras varios sondeos perdidos.

9.3 Sincronización post-partida

  1. finish_live_session() (idempotente) → schedule_postgame_sync(completed_session).
  2. PostgameSyncWorker (hilo propio) espera a que Riot procese el partido con postgame_sync_service.wait_for_match_processing (reintentos ≈12 s × 60) y descarga el desglose (objetivos, daño, participantes).
  3. Señales sync_ready/sync_progress/sync_failed → la sesión guardada se enriquece; la pestaña Partidas guardadas y el PostgameSidebar del reproductor muestran los datos.
  4. El refresco manual existe también en cada fila («Sincronizar» → request_saved_session_sync).

No grabaSin ffmpeg o carpeta inválidaInstala ffmpeg (o usa el binario de imageio-ffmpeg); revisa carpeta y límite GB.
Grabación interrumpidaSe perdieron snapshots seguidosComprueba que League sigue abierto; count_lost_snapshot() corta el vídeo de forma intencionada.

Winrates no se actualizanScraping bloqueado o sin redReintenta más tarde (delay 0.8 s); revisa la consola del build (console=True).
